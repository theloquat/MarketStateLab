# 产品、架构与接口

## 产品目标

面向希望检查市场压力、验证研究假设并追溯证据的研究人员与小团队。系统围绕“数据是否可信→市场处于什么状态→为何发出预警→如何验证或推翻假设”组织操作。

赛事任务一由多源导入、UDM、质量与分层存储承接；任务二由Kafka/Flink、特征版本、冻结统计模型和配置预警承接；任务三由独立服务、Java网关及React工作台承接。组件必须实际参与读写和恢复，容器存在本身不是完成证据。

## 服务与选型

| 组件 | 责任 | 选择原因与代价 |
|---|---|---|
| React/TypeScript | 数据、回放、特征、模型、研究、证据、监控 | 类型约束和交互复用；需要独立构建和浏览器验收 |
| Java17/Undertow | JWT、限流、REST/GraphQL/WS转发、Caffeine | 内存受限下的明确网关边界；维护Java与Python两套依赖 |
| Python / FastAPI | 数据API、模型训练/研究工具；独立特征与预警API | CPU统计建模与接口成熟；发布器进程隔离、窗口微批；仍须测量峰值容量 |
| Kafka/Flink | 日窗口、去重、滚动特征及冻结GMM/HMM/PCA推断 | 有状态计算与恢复；单broker/TaskManager不提供跨机器HA |
| MySQL | 运行、特征版本、过滤状态、幂等记录和outbox | 事务确保业务与偏移一起提交；小批量需平衡时延与吞吐 |
| Redis/Caffeine | 可重建热状态、事件广播、短时官方查询缓存 | 减少重复读取；缓存不能领先已提交数据库事实 |
| ClickHouse | 月分区时序分析物化层 | 适合历史查询；小批写入/内部采样可能产生内存压力 |
| MinIO | 原始包、Parquet、PDF、模型、Checkpoint/Savepoint | S3接口与原件归档；本机卷不是异地备份 |
| SQLite | 本地导入目录、离线参照与研究索引 | 保留轻量研究路径；不能当分布式主执行结果冒充 |

## 数据契约与数据库关系

Observation包含dataset_id、series_id、observation_date、available_date、value、quote_kind、unit、source_file、source_hash、source_row、quality_flags与event_id。event_id是规范内容哈希；业务日期、假设可得日期与处理墙钟分别记录。修订须新数据/运行版本，不覆盖旧观察。

Dataset 1:N Series；Dataset 1:N Document；Dataset 1:N Model；Model 1:N Run；Run 1:N DayFeature/State/Alert。Document 1:N PDFPage。Research记录所有者、阶段、输入版本与结果；Audit记录身份与决策；AgentCall单独记录预算和使用量。

MySQL的stream_runs主键run_id，day_features/stream_results/filter_states主键(run_id,day)，stream_alerts主键稳定告警id，worker_offsets主键(worker,partition)。outbox与ch_outbox通过稳定id保证重试幂等并有pending索引。ClickHouse按toYYYYMM(day)分区，ReplacingMergeTree按(run_id,day,id)排序，读取FINAL；不宣称跨库严格exactly-once。

ODS保留原件；DWD为带来源、单位、可得性政策的规范Parquet/文档；DWS为Flink特征和版本；ADS为状态、预警与研究结果。Kafka传输保留7日/每分区512MiB上限，过期须从归档显式重建，禁止静默跳过。MinIO与数据库卷保留，原始资料分发权限依赛事授权，不包含在公开源码包中。

## 时间、窗口与恢复

日窗口是UTC可得性日期窗口，滚动特征按20次真实观测变化计算，不假装全球交易所共享日历。不同历史运行使用独立递增逻辑watermark_date，防止共享Flink作业的水位线回退。Kafka传输时间仍是真实墙钟，避免虚拟未来日期破坏保留期。

重复在进入窗口缓冲前处理；旧日期送迟到旁路；同日冲突修订进入隔离通道并注明拒绝原因，要求新版本。Checkpoint用于故障恢复，Savepoint用于受控启停升级。消费偏移落MySQL，保留期缺口明确停止。缓存丢失可从MySQL重建。

## API与权限

REST承担具体查询和命令；GraphQL聚合只读工作台；WS推送已提交状态与预警。所有保护接口先通过网关认证，再在服务端验证内部令牌与JWT角色。写操作校验来源，API限流，GraphQL限制深度、tokens与别名数。

- GET /api/lab/summary：精简总览；GET /api/lab/tasks/{id}：按需读取完整任务结果。
- POST /api/lab/models、/evaluations：异步训练与时间评价；GET /api/lab/features/{model_id}：版本化定义。
- POST /api/lab/stream：返回task_id与run_id，界面自动订阅；GET /api/lab/stream/{run_id}：状态与预警；GET /api/lab/stream/{run_id}/progress：轻量进度。
- GET /api/features/latest/{run_id}、/api/models/{model_id}：独立特征/模型服务。
- GET /api/alerts/{run_id}：独立预警服务；POST /api/lab/stream-alerts/{id}：处理预警，以OpenAPI实际路径为准。
- POST /api/lab/research、/{id}/decision、/{id}/execute：提出、批准和执行研究。
- POST /api/lab/agent/plan：显式收费规划；GET/POST /api/lab/admin/llm：管理员连接配置。
- POST /api/lab/pdf：原件归档；GET /api/lab/pdf/{id}/pages、/original：逐页证据与原件。
- POST /graphql：例如 { dashboard }；WS /api/lab/events：真实领域事件。
- GET /docs、/openapi.json：本地Swagger与机器可读契约；GET /api/lab/reports/{name}：只读公开验证报告。

准确的参数、状态码和约束以运行版本OpenAPI为准。随机本机凭证不进入源码；localhost HTTP不构成公网TLS部署。若以后公开部署，需要明确网络与安全方案后再上线。

## 实时推断部署

默认CONTEST_INFERENCE_ENGINE=flink-compiled-v1：Flink用哈希验证的冻结模型评分，特征服务仍负责全部特征落库与查询。预警服务先把编译状态、过滤向量、告警和投递记录与消费偏移一起提交MySQL，然后经独立持久投递进入Kafka/Redis/WS。旧运行无run_config时继续Python推断，不能在同一运行中途切换模型。

发布器是数据服务监督的独立CPU子进程，不占用HTTP/WS解释器。回放速度0为最大速度，正数最少500条/秒，界面默认1000；每32条平滑配速，持久进度每500条确认。Flink网络缓冲1ms，窗口仍为1d，没有缩短业务窗口来制造延迟成绩。
