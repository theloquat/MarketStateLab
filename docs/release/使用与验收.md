# 市场状态实验室：使用与验收

更新：2026-11-08。本机验收交付版：真实功能、恢复、构建和材料可验收；按用户确认，本轮不等待独立服务器。十万条/秒持续容量和尾部时延缺口明确保留，不宣称全部性能指标达标。

## 启动

安装 Docker Desktop（建议分配 8GB 以上内存），保证本机 Python 3 可用。项目 `data/` 目录放赛事原始 ZIP，保留其原文件名；目录里应只有一个顶层 ZIP。首次启动会下载镜像并编译，需要网络。

```bash
./scripts/contest.sh start
./scripts/contest.sh credentials
```

打开 http://127.0.0.1:18080/lab。凭证命令仅在自己的终端查看，请勿录入视频或提交到 Git。管理员管理模型连接与审计；研究员训练、研究、回放和处理预警；观察员只读。30 分钟会话到期后重新登录。

`start`会核对源码构建指纹，源码变化时自动重建，避免运行旧镜像；也可先单独执行`./scripts/contest.sh build`。停止使用 `./scripts/contest.sh stop`，脚本先验证 Flink Savepoint，再停容器，不删除卷。不要使用 `down -v` 清空成果。查看状态、日志分别用 `status`、`logs`。


## 建议使用顺序

1. **数据与质量**：检查 39 个可用资产、缺失资产、来源、单位和异常记录。首次空库在全景页导入官方数据；以后台任务完成为准。
2. **模型与特征**：保留冻结 GMM 对照，训练 HMM/PCA 候选，查看特征定义和训练截止。勾选最多四个模型做时间评价。注册表默认只影响新建回放，旧运行不改版本。
3. **历史回放**：先建立离线参照；检查分布式连接，再启动 Kafka/Flink 回放。后台执行期间可以切换页面。新回放会自动选中并订阅结果，进度每2秒更新；断线后重连并补齐历史。默认每秒约1000条输入，完整区间约1分钟以上；HMM先预热，暂时无状态时检查输入/特征进度。可调阈值、冷却和速度，最大速度用于压力测试。检查概率、状态切换、预警和来源证据。
4. **研究与案例**：输入可证伪问题，选数据质量、模型比较、阈值扫描、事件、文本消融或宏观敏感性工具。创建→批准→执行→阅读证据和反证→接纳或拒绝。接纳结论不会自动变为交易策略或真实订单。
5. **文本证据**：按类别和标题检索官方资料；上传真实 PDF 可保留原件、哈希和页码。声明的发布时间不等于已核实的发布时间。
6. **运行监控**：查看组件卡片、心跳、两类待投递数、公开验证报告下载与实时事件；需要时点击事件流重连。历史业务日期和处理时间分别记录；静止期间不会制造行情或收益。

## 模型 API 与费用

管理员在“研究与案例→模型连接与预算”配置兼容 Chat Completions 的 API 根地址、模型名称和密钥；支持 DeepSeek 以及兼容服务。换服务地址必须重新填对应密钥。保存配置本身不调用模型。

点击“调用模型规划一次”才发出一次请求，默认每日最多两次、输出最多 600 tokens；失败也占用预留预算，没有自动重试。官方 DeepSeek 显式关闭思考模式以适合短结构规划；其他服务不猜测私有参数。模型提出的工具任务仍需批准。工具计算默认不花 LLM 费用。

2026-11-06 验证共两次调用、1600 tokens，其中一次思考模式截断失败、一次修复后成功。历史调用保留；不要为重录视频反复点击规划按钮，可直接展示已有记录。额度是调用/token 控制，服务商实际收费以其账单为准。

## 可复现检查

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-contest.lock
.venv/bin/python scripts/verify_release.py
.venv/bin/python -m pytest backend/tests --cov=backend/quantos
cd frontend
npm ci
npm test
npm run build
```

`verify_release.py` 访问真实本机服务、验证角色、缓存、GraphQL、WS、原始 PDF，不调用付费模型。`verify_contest_agent.py` 是显式收费联调脚本，不属于默认验收流程，请勿批量重复运行。

真实流式验收需观察任务、输出计数、outbox 和批流误差，而非只看容器绿色。失败运行 `87ae2f2bf8a94aa0b762364e` 保留为完整性失败，不能用于成功演示。本机可选择最终故障验收运行 `811c1fb306314f52a1bdf820`：64652输入/特征、861状态、26预警，多存储与离线参照一致，概率误差约1.19e-13。新环境编号不同，以本机运行列表及实际模型版本为准。首次导入约124万辅助记录可能需要数分钟，请等待后台导入任务完成。

## 当前边界

- 官方价格截至 2026-04-30，属于历史回放，不能当作今天行情。日期后第二个自然日 UTC 可用是重建假设，未获严格 PIT 认证。
- 匿名宏观不猜身份/单位；文本与事后社交指标不进入主状态模型。条件性文本消融没有展示预测增益。
- 状态可以描述市场压力，但未来十次收盘下跌 5% 的评价未胜过固定价格规则；无盈利或获奖承诺。
- 单机多服务不等于跨主机高可用。正常负载与最大速度回放的P95已有小于100ms的实测，P99仍有超标长尾；没有十万条/秒持续全链路容量证明。具体场景、数字与失败基线见性能报告。
- 依验收清单逐项验收，不覆盖未通过的指标。录制时展示已保存研究与成功运行，无需重复付费调用；实际录制、上传和提交由用户验收后进行。

## 压测与异常恢复的复现入口

完成一次真实分布式回放后可执行`verify_release.py`和`benchmark_contest_edges.py`。`benchmark_contest_pipeline.py`自动选择已训练HMM（可通过BENCH_MODEL_ID指定），建立/复用匹配离线参照，核对全部状态概率；0为最大速度，BENCH_RATE=1000为平滑配速。报告均保留时间戳。

`BENCH_SECONDS=90 BENCH_REPLAYS=1 BENCH_RATE=1000 .venv/bin/python scripts/benchmark_contest_acceptance.py`执行120用户与真实回放混合负载。`verify_compiled_recovery.py`是会真实停止赛事计算/消费服务的故障注入工具，不属于日常只读检查；只在可中断赛事回放时运行。

完整空库验收：先`./scripts/contest.sh build`，再运行`.venv/bin/python scripts/verify_clean_contest.py`。它使用独立 Compose 项目、临时端口、全新卷和随机凭证。验收通过后回收临时项目和卷。失败时保留诊断日志在 tmp。建议为测试准备额外磁盘与内存。

Kafka保留期缺口会停止消费而不是跳过数据。若实际出现过期缺口，需要从原始归档显式重建流运行并保留旧审计结果；不应手工把offset直接推进或删除数据库来伪装恢复。
