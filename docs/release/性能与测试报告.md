# 本机性能、测试与可靠性报告

独立版本验证：2026-11-21。压力测量：2026-11-08。交付范围按用户确认：先交付本机版本，独立服务器容量验证暂不进行。下列指标逐项判定，不以局部计算时间替代端到端，也不把P95达标说成所有样本达标。

## 环境与测量口径

开发机macOS/arm64，约16GB物理内存、10逻辑CPU；Docker约8GB内存，同一主机产生测试负载。单broker、单TaskManager，真实MySQL、Redis、Kafka、ClickHouse、MinIO与Java网关均参与。不是跨主机高可用或独立负载机测试。

端到端起点为Flink日窗口触发的墙钟，终点为客户端收到已持久化状态；包含特征、冻结推断、Kafka、SQL事务、持久outbox、Redis、Python/Java WebSocket与客户端。它不包括等待一天业务窗口，也不包括水位线之前的源接入。跨容器使用同机墙钟，另保留真实处理时间戳。

输入配速0表示最大速度；1000表示每秒约1000条、每32条平滑配速。完整回放速率包含发布进程启动、数据准备、预热与处理，不是持续容量上限。单次64652条输入远不足以证明持续超过十万条每秒。

## 优化过程与负结果保留

旧路径逐窗口SQL、逐事实分析outbox与忙轮询造成积压。失败基线端到端P95曾达到46秒，之后窗口信封和微批约8秒，再到约600ms。所有原始报告保留。后续采用紧凑Flink状态、单次批上下文读取、批事务与偏移共同提交、持久投递/分析物化隔离、独立发布进程和Flink冻结推断。分段时钟定位约99ms网络缓冲，改为1ms后测得上述结果；低缓冲会牺牲部分峰值吞吐，需要另外测容量。

不能仅凭本机几千条/秒回放速率断言这是硬件上限；实现、单分区、按运行顺序处理、负载生成和数据规模也影响结果。独立环境可帮助继续测试，但不保证买服务器就会达标。本轮不购置、不申请云资源。

## 测试与正确性

独立仓库测试数量及覆盖见 `standalone-test-summary.json`。Python 按 backend/marketlab 计算，前端按状态实验室组件计算，Java 分别报告 Flink 和网关。

合成黄金样本核对GMM/HMM、有/无PCA、逐步前向状态及非法输入。真实完整回放包含64652观察/特征、2406日窗口、861状态、26预警，与离线参照最大概率误差约1.19e-13。MySQL、ClickHouse FINAL、Redis与MinIO检查点逐项核对；不宣称跨库严格exactly-once。

最终真实故障报告`compiled-recovery-20261108-211039.json`：发布35000条后SIGKILL TaskManager及特征/预警消费服务，恢复时间及结果详见原始报告；最终全部计数一致、outbox为0。重复不再输出；迟到、同日冲突、非法日期和破损JSON被隔离，作业继续运行。

诊断中曾因ClickHouse宽列排序查询超过256MiB限制而失败，随后改为按索引定位原始规范行；Kafka探针起点解析也修正为明确broker结束偏移并增加进程超时。失败记录见`recovery-probe-failure-20261108.json`，不伪装成应用成功测试。
