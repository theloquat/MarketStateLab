# ADR 0003：历史日期、回放水位线与Kafka传输时钟

日期：2026-11-04；状态：经真实多次回放和故障测试后采用。

首轮独立流式回放与批处理完全一致，但第二轮从2019年重新播放时，共享Flink作业的水位线已在2026年，部分预热期记录被判迟到。严格的全窗口对照发现152个窗口/4000条特征缺失，即使最终861个状态和13条预警相同，也判为失败并保留隔离记录。

采用三种独立时间：

1. `observation_date`与`available_date`保留历史业务含义，用于模型输入、证据和评估。
2. `watermark_date`是历史回放调度时钟。MySQL事务为每个运行分配不重叠的整日偏移，Flink据此执行1d UTC事件时间窗口。输出业务日期仍取原available_date。
3. Kafka记录传输时间使用生产者实际壁钟。不能把可能位于未来的回放水位线直接写为Kafka消息时间，否则会触发broker未来时间限制并影响保留策略。

暂停未完成的发布会阻止新建下一个运行，MySQL会话锁防止两个发布器交错。发布游标在消息确认、原始物化后提交。重复/真实迟到由Flink去重或写入独立late主题，不修改旧业务版本。数据修订需要新版本和新运行。

修复后的运行7e516e9dc67e4316a7321c97：35000条处暂停、稳定checkpoint、强制终止TaskManager、恢复并继续，2406个日窗口/64652条特征/861状态/13预警与参照一致。详细机器报告另外归档。

代价：这条管道明确是历史回放实验，不冒充真实逐笔市场吞吐。当前单分区、单并行度用于验证数学与恢复，分区扩展、跨运行状态回收、Kafka游标过期和多主机高可用属于后续性能与运维验收。
