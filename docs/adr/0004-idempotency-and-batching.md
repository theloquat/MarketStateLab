# ADR 0004：幂等业务效果与批量物化

日期：2026-11-04；状态：真实回放内存问题后采用。

Flink checkpoint保存在MinIO，Kafka sink至少一次传输。日窗口之前按run/series保留最新观测身份，过滤重复、隔离旧日期，并拒绝同日冲突修订，避免重发消息在窗口中累积。固定官方日频契约每个资产每天只有一个观测；未来扩展到盘中多条有效观测时须增加增量聚合，不沿用此日频约束。MySQL以run/day、事件ID和预警ID保证重复消费不重复业务结果，保存Kafka通知与ClickHouse物化的持久化outbox。发送成功后再标记；崩溃可能重发，由稳定ID处理。

ClickHouse使用按月份分区的ReplacingMergeTree，查询验收使用FINAL。后台合并不是即时唯一约束。首次逐日小写入造成较多数据碎片并触发650MB服务内存限制，因此改为MySQL持久待写队列、最多1500行批量物化；通过MySQL会话锁允许任一消费者接管未完成批次。

Redis仅为可重建热状态：相同运行的旧事件不能覆盖较新日期；缓存不存在时从MySQL最新状态恢复。

本机测试中MySQL、ClickHouse限额按实际错误调整为768MiB、1400MiB；ClickHouse自身内存上限10亿字节，避免按900MiB容器额度宣称650MB足以持续回放。配置不是性能成绩。

不声称跨MySQL/CH/Redis/Kafka有统一事务或全链路exactly-once。C5继续验证更多故障组合、持续压力、outbox滞后与资源曲线；本批报告只证明真实样本的结果一致性和已执行的恢复。
